# Security and Privacy Audit

**Date:** 2026-11-05 | **Scope:** the running production-overlay stack (Caddy, web BFF, API, Keycloak, PostgreSQL, Neo4j, SeaweedFS, Qdrant, inference) plus a read of the code paths named below. This is a developer audit, not a penetration test. No external tester has reviewed it.

## Verified by running something

| Area | Check | Result |
|---|---|---|
| Public surface | `docker ps` ports | Only Caddy publishes ports (80, 443). Databases, API, Keycloak, SeaweedFS, Qdrant are on internal networks |
| Transport | `curl -I https://localhost/login` | HSTS (1 year, includeSubDomains) present |
| Browser headers | same | `X-Frame-Options: DENY`, `nosniff`, `Referrer-Policy`, `Permissions-Policy` present. **CSP was missing; now added** |
| Unauthenticated access | API `/v1/dashboard`, `/v1/documents` without token | 401 problem+json. Page routes redirect to login (307) |
| Keycloak admin | `/auth/admin/master/console/`, master realm | 404 through Caddy |
| Token validation | pytest `test_bad_tokens_are_rejected` | Expired, wrong audience, wrong issuer, wrong key all rejected |
| User isolation | `test_cross_user_access_is_404`, RLS tests | Another user's resource returns 404. With RLS on, other users' rows are invisible to the restricted role |
| RLS | `pg_roles`, `pg_class` on the live database | API role `vaakya_api`: not superuser, no BYPASSRLS. 20 tables have RLS enabled and forced |
| Request size | `test_oversized_json_is_413` | Enforced |
| Dependencies | `npm audit` (all and production), `pip-audit` | 0 known vulnerabilities |
| CSRF | new E2E test | Proxy returns 403 for a write with a foreign `Origin` |

## Verified by reading code (not exercised by an attack)

- **Uploads** (`api/vaakya/services/documents.py`): image content is decoded and verified, size and pixel limits apply (decompression-bomb guard), images are re-encoded so EXIF/GPS and PNG text chunks are dropped, PDFs with passwords, JavaScript, auto-actions or embedded files are rejected, page count is capped. Files are encrypted with AES-256-GCM per file before storage (SeaweedFS), key from `VAAKYA_VAULT_KEK_B64`.
- **Session**: BFF cookie is `httpOnly`, `SameSite=Lax`, `Secure` when the app URL is https. Tokens stay on the server.
- **Secrets**: generated by `init-secrets.sh` into `infra/secrets/` (git-ignored), mounted as Docker secrets or env files. `VAAKYA_ENV=production` refuses to start with the default log HMAC key.
- **Privacy**: identifiers (10 Indian types) are redacted before any reasoning model; the data-flow audit records categories, not content; consent is checked before document storage.

## Fixed in this audit

| Severity | Issue | Fix |
|---|---|---|
| MEDIUM | No Content-Security-Policy | CSP in `web/next.config.ts` (`default-src 'self'`, `object-src 'none'`, `frame-ancestors 'none'`, `base-uri 'self'`) |
| MEDIUM | CSRF relied on SameSite=Lax alone | Origin check on non-GET proxy calls |
| LOW | `/docs` and `/openapi.json` on in production (internal network only) | Disabled when `VAAKYA_ENV=production`, with a test |

## Open findings

| Severity | Finding | Recommendation |
|---|---|---|
| MEDIUM | CSP still allows `'unsafe-inline'` for scripts and styles (Next.js inline bootstrap) | Move to nonce-based CSP via middleware once the UI is stable |
| MEDIUM | `/metrics` on the API is unauthenticated (reachable only inside the Docker network) | Keep it off public routes; add a token if Prometheus runs on another host |
| MEDIUM | TLS is Caddy's internal CA for `localhost`; the public deployment, domain and certificate handling are untested | Test with a real domain before launch |
| MEDIUM | No rate-limit or lockout test was run against the live stack in this audit (Keycloak brute-force protection is configured; API rate limits exist in code) | Add tests, including limits behind Caddy (client IP forwarding) |
| LOW | Demo account password is printed by `init-secrets.sh` and the demo users exist in any seeded database | Never seed demo users on a public server |
| LOW | No container image vulnerability scan (Trivy or Grype) was run | Add to CI |
| LOW | Dependency and licence review: copyleft items (psycopg LGPL, Neo4j GPLv3, Grafana/Loki AGPLv3) await owner decision D-031 | Owner |
| INFO | No external penetration test, no threat model document beyond architecture notes (T10.08) | Before any public launch |

## Privacy position

The product stores only what the user types or confirms, plus uploaded documents (encrypted) with the user's consent. It does not connect to banks. No real user data exists yet, and DPDP/SEBI legal scoping (T0.14) has not happened. Do not describe the product as compliant with either.
